## Control animation

<p>Use <code>clock: 'auto'</code> for automatic animation. domfx advances effect time while it can render, skipping time spent paused, hidden or offscreen. <code>'ambient'</code> is the older spelling of the same behavior and remains supported. The instance's read-only <code>clock</code> preserves the spelling you supplied.</p>

<p>Use <code>clock: 'manual'</code> for external control through your code or GSAP. domfx never advances time in this mode, including after <code>resume()</code>. It still observes the target and schedules rendering for the next frame.</p>

<p><code>time</code> selects a point in the effect's animation in seconds. It is neither progress from 0 to 1 nor elapsed wall-clock time. You can seek backward or use negative values. Let only one animation driver write each property.</p>

## Reduced motion

<p>The default <code>motion: 'respect'</code> suppresses output when the user requests reduced motion. After the preference changes back, explicitly call <code>retry()</code>. It does not automatically replace animation with a still frame.</p>

<p><code>motion: 'static'</code> always renders a still effect at time zero, under either preference. Time writes remain readable but do not change its rendered frame. Intensity and capture updates still work. <code>resume()</code> does not animate it.</p>

<p>See <a href="/docs/api/effect-handle">effect state and methods</a> for readiness, pause/resume, refresh, retry and cleanup.</p>
