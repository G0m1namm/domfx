<p>Animate any effect with ordinary GSAP property tweens. The effect instance exposes numeric <code>time</code> and <code>intensity</code> setters. No domfx plugin registration or <code>@domfx/gsap</code> import is needed.</p>

<p>Follow the <a href="/docs/installation#add-the-optional-gsap-binding">installation guide</a> and add GSAP to your app. This example uses Fire; replace its import and omit <code>flameHeight</code> to use another effect.</p>

## Provide your elements

<p>Run after mount. In <code>main.ts</code>, find the elements from the preview HTML:</p>

## Build your sequence

<p>Create the effect with <code>clock: 'manual'</code> so GSAP controls its time. The container fades in over half a second; the effect then moves from time 0 to 4 and intensity 0.8 to 0.4 over four seconds. Fade the container so the original target and effect share opacity. Target-only opacity changes are unsupported.</p>

## Seek and play

<p>Use <code>timeline.play()</code>, <code>pause()</code>, <code>seek()</code> and <code>reverse()</code>. At <code>timeline.seek(2.5)</code>, effect time is 2 and intensity is 0.6. Seeking backward to 1.5 gives time 1 and intensity 0.7. Callback-suppressed seeks still update the setters; an <code>onUpdate</code> copy is unnecessary.</p>

<p>Chain <code>.to()</code> calls to animate from preceding destinations. Use <code>.from()</code> or <code>.fromTo()</code> for explicit starting values, remembering their default immediate rendering. Later <code>.fromTo()</code> segments commonly need <code>immediateRender: false</code>. Easing, <code>repeat</code>, <code>yoyo</code>, <code>overwrite</code> and <code>timeScale()</code> follow normal GSAP conventions.</p>

<p><code>gsap.killTweensOf(fire, 'intensity')</code> stops only that property; it does not dispose the effect or stop a time tween. Keep one driver per property and keep values within the <a href="/docs/api/shared#control-playback">control ranges</a>.</p>

## Own the lifetime

<p>Call <code>cleanup()</code> on unmount. It removes the disposal listener, kills the timeline this example created and disposes the effect. Registration before <code>ready</code> settles covers navigation during setup. The disposal listener also stops this timeline if removing the target disposes the effect.</p>

<p>When borrowing a timeline, retain and kill only your child tweens; its owner cleans up the timeline and siblings. Finishing, killing or overwriting a tween does not release its target's resources.</p>

<span id="context-cleanup" />

### GSAP context cleanup

<p>Create tweens inside <code>gsap.context()</code> and return explicit resource cleanup. Register synchronously; a context does not automatically collect work created later by arbitrary promise continuations.</p>

<div class="docs-code-scroll" tabindex="0" role="region" aria-label="GSAP context resource cleanup"><Code code={`const context = gsap.context(() => {
const effect = attachFire(target, { host, clock: 'manual' });
const tween = gsap.to(effect, {
  time: 4, intensity: 0.4, duration: 4, ease: 'none',
});
const unsubscribe = effect.onDispose(() => tween.kill());
return () => {
  unsubscribe();
  tween.kill();
  effect.dispose();
};
});
// On unmount, even before setup finishes:
context.revert();`} lang="ts" theme={codeTheme} /></div>

## Optional lifecycle helpers

<p><code>@domfx/gsap</code> provides <code>bindEffect</code> and <code>bindEffectAsync</code> for snapshot bindings with explicit cleanup responsibility. The asynchronous helper safely disposes results arriving after cancellation. The compatible <code>bindFire</code> names remain available for all effects.</p>

<p>These helpers capture starting controls when created and animate private proxy targets. They differ from native chained <code>.to()</code> calls, target-based kill and overwrite. Use the <a href="/docs/api/gsap#snapshot-bindings">binding reference</a> when you need that contract; prefer native tweens for ordinary sequencing.</p>

<span id="unavailable-and-retry" />

## Unavailable output and retry

<p>The main example starts playback only when the effect is active. Missing GPU support or reduced motion preserves the original target. Correct the condition, then await <code>fire.retry()</code>, inspect its state and play the existing timeline. Retry retains controls; it does not require another tween.</p>
