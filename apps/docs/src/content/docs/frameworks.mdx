<p>These recipes tie an effect's lifetime to a component. Copy them into your app and change them as needed: they are your code, not a domfx package. Install <code>@domfx/browser</code> as shown in the <a href="/docs/installation">installation guide</a> first.</p>

<p>Each recipe has two parts: a small hook or composable that owns one effect, and a Fire button that uses it. Both take the same settings:</p>

<ul>
<li><code>attach</code>: the effect, such as <code>attachFire</code>.</li>
<li><code>options</code>: creation-only values, such as <code>flameReach</code>. A changed value replaces the effect.</li>
<li><code>controls</code>: writable values, such as <code>intensity</code> and <code>color</code>. They update the live effect.</li>
<li><code>refreshOn</code>: values that restyle the host. A change calls <code>refresh()</code>.</li>
</ul>

<p>Both return <code>lifecycle</code> and <code>reason</code>, so the component can style a fallback.</p>

## How the recipes own the effect

<ul>
<li>Cleanup is registered before waiting for fonts. Unmounting during setup never creates a late effect.</li>
<li>React StrictMode mounts twice in development. The first cleanup runs before fonts are ready, so only one effect attaches.</li>
<li>Unmounting disposes the effect and removes its canvas. Remounting attaches a fresh effect; a disposed effect cannot be reused.</li>
<li>Control writes render on the next frame without recapturing the target. Creation-only options need a new effect.</li>
<li>Changes inside the target refresh automatically. Style changes on the host, ancestors or stylesheets need <code>refresh()</code>.</li>
<li>An unavailable or suspended effect leaves the button working. The button sets <code>data-effect</code> from <code>lifecycle</code>, and its CSS shows a static glow instead. Branch on <code>reason</code> as shown in <a href="/docs/troubleshooting">troubleshooting</a>.</li>
</ul>

## Use another effect

<p>Replace <code>attachFire</code> and its options in the component, for example with <code>attachFrost</code> and <code>coatingDepth</code>. The hook and composable work with every <code>attach*</code> function. Each <a href="/docs/api/effects">effect reference</a> lists its creation options and writable controls.</p>

## Server rendering and GSAP

<p>Effects are client-only. The recipes attach after mount, so server rendering outputs the plain button, and <code>'use client'</code> keeps the React component out of server components. They were tested with Vite, not with Next.js or Nuxt.</p>

<p>For a timeline, follow the <a href="/docs/gsap">GSAP guide</a> and call its <code>cleanup()</code> from the same teardown: the <code>useEffect</code> cleanup or <code>useGSAP</code> in React, the watcher cleanup or <code>onBeforeUnmount</code> in Vue.</p>
